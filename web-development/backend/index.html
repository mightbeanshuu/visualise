Lesson 01: API for Smart Recommendation Engine

Follow the mentor structure. Do not memorize code; derive it from the backend job.

FIRST PRINCIPLES

1. Big Picture

A backend exists because the browser should not own secrets, databases or business rules. For a Smart Recommendation Engine, the frontend sends user context, the backend validates it, reads product data, runs recommendation logic, stores feedback later, and returns clean JSON.

3. Real World Analogy

Restaurant: the customer does not enter the kitchen. The waiter receives the order, checks it, sends it to the kitchen, and returns the prepared dish. The backend is the waiter plus kitchen workflow.

4. Thinking Process

  1. I need to receive requests from the frontend.
  2. I should not put all logic in one file.
  3. I need a route for recommendation requests.
  4. I need a controller to translate HTTP into application logic.
  5. I need a service where recommendation thinking lives.
  6. I need a database later, but first I can use sample data.

5. English Algorithm

Receive request
↓
Read interest
↓
Validate interest exists
↓
Fetch candidate products
↓
Score or filter products
↓
Return top recommendations as JSON

6. Code

import express from "express";

const app = express();
const PORT = 3000;

const products = [
  { id: 1, name: "React Mastery", tags: ["frontend", "react"] },
  { id: 2, name: "Node API Builder", tags: ["backend", "node"] },
  { id: 3, name: "System Design Basics", tags: ["backend", "architecture"] }
];

app.get("/recommendations", (req, res) => {
  const userInterest = req.query.interest;

  if (!userInterest) {
    return res.status(400).json({ error: "interest is required" });
  }

  const recommendations = products.filter(product =>
    product.tags.includes(userInterest)
  );

  return res.json({ recommendations });
});

app.listen(PORT, () => {
  console.log(\`Server running on port \${PORT}\`);
});

7. How Could I Write This Myself?

Start from: “When the browser asks for recommendations, I return matching products.” Nouns become data: products, tags, recommendations. Verbs become routes/functions: ask, filter, return. Express only connects HTTP to that thinking.

8. Common Beginner Mistakes

  • Putting database logic, route logic and scoring logic in one file forever.
  • Returning HTML instead of JSON for an API route.
  • Not validating query/body inputs.
  • Thinking Express is the backend; Express is only the HTTP layer.
  • Skipping project thinking and memorizing syntax first.

9. Interview Questions

  1. What is the job of a backend server?
  2. What is the difference between route, controller and service?
  3. Why should recommendation scoring not live directly inside a route handler in a large app?

10. Mini Assignment

Add support for GET /recommendations?interest=frontend and return only frontend-related products. Do not add a database yet.

11. If I Get Stuck

  1. Hint 1: Where does request input live?
  2. Hint 2: Which array method keeps matching items?
  3. Hint 3: What should happen if interest is missing?
  4. Answer comes only after you try.
